# Gold Trading Dashboard

A company-grade MERN trading cockpit for XAUUSD.

## Stack
- **Frontend:** React + TypeScript + Vite + MUI (dark gold theme) + Recharts
- **Backend:** Node + Express + TypeScript + Mongoose
- **Database:** MongoDB
- **Cache:** Redis (gold price)
- **Deploy:** Render (backend as a Docker web service, frontend as a static site), MongoDB Atlas, Redis via Upstash (or similar) — see [Production Deployment](#production-deployment) below.

## Features
- Live gold (and ETHUSD) price with 10s refresh, market news
- Trade journal: create / edit / close / delete, screenshots, playbook-driven pre-trade checklist
- CSV + Excel import/export (MT5 Deals/Positions)
- Auto position sizing from balance × risk %, or a manual lot override
- Risk/reward calculator with price-level SL/TP and a Log-to-Journal handoff
- Balance cascade with tax reserve (SARS)
- Equity curve, win rate, months-to-$1M projection, analytics dashboard
- Goals and playbooks
- Risk Mentor: rule-based coaching from your own trade history (loss streaks,
  drawdown, overtrading, discipline adherence), with attributed trading/self-help
  book quotes
- Daily journal + mood tracking on the calendar, with a mood-vs-P&L view

## Local Development

### Docker (recommended)
```bash
docker compose up
```
This starts MongoDB, Redis, the backend (port 5000) and the frontend (port 5173,
served by nginx on its container's port 80). It expects a `gold-net` external
Docker network — create it once with `docker network create gold-net` if you
haven't already.

### Without Docker
```bash
# Backend
cd backend
cp .env.example .env   # fill in MONGO_URI, JWT_SECRET, etc.
npm install
npm run dev

# Frontend (separate terminal)
cd frontend
cp .env.example .env
npm install
npm run dev
```

## Production Deployment

This app is deployed on **Render**, with the frontend on
`app.goldholdings.co.za`.

### One-time setup
1. **MongoDB Atlas** — create a free-tier cluster, add a database user, and
   copy the connection string for `MONGO_URI`.
2. **Redis** — create a free instance on a provider such as Upstash, and copy
   its connection string for `REDIS_URL`.
3. **Render** — connect this GitHub repo and create the two services
   described in `render.yaml` (Render can read that Blueprint directly via
   "New +" → "Blueprint", or you can create the two services manually):
   - `gold-dashboard-backend` — Docker web service built from `backend/Dockerfile`.
   - `gold-dashboard-frontend` — static site built from `frontend/` (`npm install && npm run build`, publish `dist`).
4. On the **backend** service, set in the Render dashboard:
   `MONGO_URI`, `REDIS_URL`, `GOLD_API_KEY` (the values `render.yaml` leaves
   blank for you to fill in — `JWT_SECRET` is auto-generated by Render).
5. On the **frontend** service, set `VITE_API_URL` to the backend service's
   Render URL (or your own `api.goldholdings.co.za`, if you set one up) plus
   `/api`.
6. **DNS** (at your registrar, e.g. Afrihost) — add a CNAME record:
   `app` → the Render-provided hostname for the frontend service. Add the
   custom domain `app.goldholdings.co.za` in the frontend service's Render
   settings so Render provisions the TLS certificate for it.
7. **Create your one real account** — temporarily set `ALLOW_REGISTRATION=true`
   on the backend and `VITE_ALLOW_REGISTRATION=true` on the frontend, redeploy
   both, register through the app, then set both back to `false`/unset and
   redeploy again. **Do this once.** This app has a single shared dataset with
   no per-user data separation — a second registered account would see and be
   able to edit the same real trading/financial data, not a separate account.

### Every subsequent deploy
Push to `main` — Render auto-deploys both services from GitHub.
